
# PLANNING & REQUIREMENT BREAKDOWN

# Core Problem Analysis
- MRPL’s actual problem is not “we need another chatbot.”

# The real problem is:
    - Sensitive industrial knowledge work cannot leave the organization, while modern AI productivity tools are mostly cloud-hosted and therefore unsuitable for confidential refinery, PSU, government, defence-linked, engineering, legal, procurement and financial workflows.


# The system therefore has to satisfy five requirements simultaneously:

1. Sovereignty
- No prompt, document, embedding, image, source code or telemetry leaves the premises.
- Internet connectivity must not be required after installation.
- Sovereignty must be provable, not merely claimed.

2. Agentic execution
- User gives a goal, not a single prompt.
- System plans multiple steps.
- Agents read files, retrieve internal knowledge, execute code, create documents and verify outputs.

3. Model independence
- Multiple open-weight models.
- Automatic task-based model routing.
- Models can be added/replaced without rewriting the application.

4. Multimodal industrial understanding
- PDFs.
- Scans.
- Images.
- engineering drawings/P&IDs.
- handwritten notes.
- spreadsheets.
- source code.

5. Deliverables rather than chat
- DOCX.
- PPTX.
- XLSX.
- reports.
- validated code.
- calculations.
- approval notes.

The winning product narrative should therefore be:
A sovereign AI execution platform for confidential enterprise work — not a local ChatGPT clone.
